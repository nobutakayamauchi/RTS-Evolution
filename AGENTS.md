# AGENTS.md

## Repository role
RTS Evolution is the next-generation canonical reconstruction of RTS responsibilities from surviving principles and current external capabilities.

## Load order
1. Read `README.md`.
2. Read only the current canonical specification/status documents required by the active responsibility.
3. Use the original `nobutakayamauchi/RTS` only for historical evidence, abolition/freeze records, or reconstruction history.
4. Use `nobutakayamauchi/Ultimate-Loop` for the canonical development method when method-level guidance is required.

## Source of truth
- Current RTS Evolution canonical documents outrank old RTS implementation assumptions.
- Original RTS is historical evidence, not the default current architecture.
- Preserve UNKNOWN/CONFLICT when migration or responsibility ownership is unresolved.

## Context budget
- Do not recursively load the old RTS repository or WITNESS history by default.
- Start from the current responsibility and load predecessor evidence only when needed to justify continuity or replacement.

## Human gates
Architecture promotion, public exposure, destructive migration, repository visibility, deployment, external actions, or irreversible changes require explicit human approval.

## Stop conditions
Stop when a responsibility has not survived necessity testing, predecessor/current guidance conflicts, or evidence is insufficient to claim canonicalization or completion.
